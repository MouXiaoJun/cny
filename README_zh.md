# cny — 人民币金额转中文大写

将人民币金额(数字)转换为**中文大写数字**(财务大写),用于需要展示大写金额的文书场景。本库只生成金额文本,不添加“人民币”前缀,不校验票据模板,不承诺法律合规。

- 模块:`github.com/MouXiaoJun/cny`
- Go 版本:1.21+,零依赖(仅标准库)
- 许可:[MIT](LICENSE)

```go
s, _ := cny.ConvertCents(1234567890) // 精确整数分
fmt.Println(s) // 壹仟贰佰叁拾肆万伍仟陆佰柒拾捌元玖角
```

## 特性

- **财务大写字符**:壹贰叁肆伍陆柒捌玖拾佰仟万亿角分元整负
- **完整的零规则**:1001 → 壹仟零壹元整、105 → 壹佰零伍元整、100 → 壹佰元整(最容易出错的部分,已全覆盖测试)
- **万 / 亿 / 万亿 / 亿亿** 全分组支持,整数部分最多 20 位
- **小数**:角、分;无角分写"整";不足壹角如 0.05 → 伍分
- **负数**:-100 → 负壹佰元整
- **精度**:超过 2 位小数按**十进制四舍五入到分**(见 [精度设计](#精度设计四舍五入到分))
- **两条路径**:`Convert`(float64)与 `ConvertCents`(整数分,精确无浮点误差)
- 明确错误:`ErrNotFinite`(NaN/±Inf)、`ErrOutOfRange`(超出支持范围)
- 测试:单元测试 + 模糊测试(FuzzConvert / FuzzConvertCents)+ 基准测试

## 快速开始

```go
package main

import (
	"fmt"

	"github.com/MouXiaoJun/cny"
)

func main() {
	for _, amount := range []float64{
		0, 100, 105, 1001, 12345678.90, 0.05, 1.05, -100, 1.005,
	} {
		s, err := cny.Convert(amount)
		fmt.Printf("%14.2f => %s (err=%v)\n", amount, s, err)
	}
}
```

输出:

```

      1001.00 => 壹仟零壹元整 (err=<nil>)
  12345678.90 => 壹仟贰佰叁拾肆万伍仟陆佰柒拾捌元玖角 (err=<nil>)
         0.05 => 伍分 (err=<nil>)
         1.05 => 壹元零伍分 (err=<nil>)
      -100.00 => 负壹佰元整 (err=<nil>)

```

## API

### `func Convert(amount float64) (string, error)`

将金额(元,float64)转换为中文大写字符串。

| 输入 | 输出 |
| --- | --- |
| `0`、`0.00`、`-0.0` | `零元整` |
| `100` | `壹佰元整` |
| `105` | `壹佰零伍元整` |
| `1001` | `壹仟零壹元整` |
| `100000001` | `壹亿零壹元整` |
| `12345678.90` | `壹仟贰佰叁拾肆万伍仟陆佰柒拾捌元玖角` |
| `0.05` | `伍分` |
| `1.05` | `壹元零伍分` |
| `-100` | `负壹佰元整` |
| `1.005` | `壹元零壹分`(四舍五入到分) |
| `NaN` / `±Inf` | 错误 `ErrNotFinite` |
| `1e20`(整数部分 21 位) | 错误 `ErrOutOfRange` |

### `func ConvertCents(cents int64) (string, error)`

以**整数分**(1 元 = 100 分)为单位转换,无浮点误差。适合数据库以 BIGINT 存储分、第三方支付返回分值等场景。支持 `int64` 全范围(`math.MaxInt64` / `math.MinInt64` 均正确),永不返回错误。

```go
s, _ := cny.ConvertCents(1234567890) // 壹仟贰佰叁拾肆万伍仟陆佰柒拾捌元玖角
```

### 错误

```go
var (
	ErrNotFinite  // amount 为 NaN 或 ±Inf
	ErrOutOfRange // 四舍五入后整数部分超过 20 位(≈ |amount| ≥ 10^20)
)
```

均支持 `errors.Is`:

```go
s, err := cny.Convert(amount)
if errors.Is(err, cny.ErrNotFinite) {
	// 处理非有限数值
}
```

## 转换规则

### 数字与单位

| 数字 | 壹 贰 叁 肆 伍 陆 柒 捌 玖 |
| --- | --- |
| 位置单位(组内) | 拾(10) 佰(10²) 仟(10³) |
| 分组单位(四位一组) | 万(10⁴) 亿(10⁸) 万亿(10¹²) 亿亿(10¹⁶) |
| 货币单位 | 元、角、分、整(本库不输出“正”) |
| 符号 | 负 |

> 说明:10¹² 写作“万亿”、10¹⁶ 写作“亿亿”是本库的分组约定,不代表所有票据接受这种超大金额写法。

### 整数部分

按四位一组从高位到低位读,组内遵循**拾佰仟**:

| 输入 | 输出 |
| --- | --- |
| 1 | 壹元整 |
| 10 | 壹拾元整 |
| 20 | 贰拾元整 |
| 100 | 壹佰元整 |
| 10000 | 壹万元整 |
| 100000 | 壹拾万元整 |
| 100000000 | 壹亿元整 |
| 12345678 | 壹仟贰佰叁拾肆万伍仟陆佰柒拾捌元整 |

### 零的规则(重点)

规则:**非零数字之间出现连续零时只读一个"零";数字末尾的零不读;整组为零(如万位组、亿位组整体为零)时,若上下均有非零组则补一个"零"**。

| 输入 | 输出 | 说明 |
| --- | --- | --- |
| 100 | 壹佰元整 | 末尾零不读 |
| 105 | 壹佰零伍元整 | 十位为零 → 一个零 |
| 1001 | 壹仟零壹元整 | 连续零只读一个 |
| 1010 | 壹仟零壹拾元整 | 个位零不读,只读十位间的零 |
| 10001 | 壹万零壹元整 | 组间零 |
| 10000001 | 壹仟万零壹元整 | 组内千位非零、万位为零 → 补零 |
| 10010000 | 壹仟零壹万元整 | 万位组内零 |
| 100010000 | 壹亿零壹万元整 | 亿与万之间的零 |
| 123400000001 | 壹仟贰佰叁拾肆亿零壹元整 | 万亿之间整组为零 → 一个零 |

### 小数部分

| 情形 | 规则 | 示例 |
| --- | --- | --- |
| 无角无分 | 元后写"整" | 100 → 壹佰元整 |
| 有角无分 | 只写角,不写"整" | 1.50 → 壹元伍角 |
| 有分 | 角位为零时在元后补"零" | 1.05 → 壹元零伍分 |
| 不足壹角 | 直接写分,省略"零元" | 0.05 → 伍分 |
| 整数部分为零 | 省略"零元" | 0.55 → 伍角伍分 |

### 负数

负数以"负"开头,其余规则不变:

- -100 → 负壹佰元整
- -1.05 → 负壹元零伍分
- -0.05 → 负伍分

`-0.0` 视为零,输出 `零元整`(不写"负")。

### 零元整

`0`、`0.00`、`-0.0`、以及四舍五入后归零的金额(如 `0.004`)统一输出 **`零元整`**。

> 这是本库的既定输出,在测试中固定;具体文书要求由调用方核验。

### 有来源的金额样例

[人民银行《支付结算办法》附一原件](https://www.pbc.gov.cn/tiaofasi/144941/144957/3601571/2018081309061735002.pdf)(PDF 第 69–70 页)给出金额书写示例;可读交叉来源为[北京市交通委招标文件附录](https://jtw.beijing.gov.cn/xxgk/ztbxx/202005/P020200528617926701667.pdf)(印刷页码 40)。以下三项已固定为回归样例,仅比较金额文本,“人民币”前缀由调用方模板处理:

| `ConvertCents` 输入 | 金额文本 |
| --- | --- |
| `140950` | 壹仟肆佰零玖元伍角 |
| `600714` | 陆仟零柒元壹角肆分 |
| `1640902` | 壹万陆仟肆佰零玖元零贰分 |

核查日期:2026-08-30。这些样例不构成合规审核;负数、不足一元省略“零元”、万亿/亿亿等属于本库约定,不据此推定适用于所有票据。

## 精度设计(四舍五入到分)

### 设计决策:舍入,而非报错

输入精度超过 2 位小数(如 `1.005`、`2.675`)时,本库**按十进制四舍五入到分**,不报错:

- 只看小数点后**第三位**,`≥ 5` 进一、`< 5` 舍去(半进);
- 舍入作用于**绝对值**,符号保持不变:`-1.005 → 负壹元零壹分`;
- 进位会传播到整数部分:`0.999 → 壹元整`、`9.995 → 壹拾元整`。

| 输入 | 输出 |
| --- | --- |
| 1.004 | 壹元整 |
| 1.005 | 壹元零壹分 |
| 2.675 | 贰元陆角捌分 |
| 0.004 | 零元整 |
| 0.005 | 壹分 |
| -1.005 | 负壹元零壹分 |
| 1.23456789 | 壹元贰角叁分 |

### 为什么不用 `amount * 100` 取整

`float64` 是二进制浮点,不能精确存储 `1.005`。若按 `math.Round(amount*100)` 计算可能得到 `1.00`,与对十进制字符串 `1.005` 四舍五入的结果不同。

本库使用收到的浮点值的**最短可往返十进制表示**参与舍入,`1.005` 表示为 `1.005`,第三位为 5 → 进位 → `壹元零壹分`。[strconv.FormatFloat 文档](https://pkg.go.dev/strconv#FormatFloat)的往返保证针对同一个浮点值,不能恢复传入前丢失的原始十进制信息。

### float64 的固有限制

不能用 `2⁵³/100` 元作为任意 float64 金额的分精度保证。在 `2⁴⁶` 元附近,相邻 float64 已相差 0.015625 元,超过 1 分。例如 `cents := int64(7036874417766401)` 经 `float64(cents)/100` 后转换,金额结尾为“贰分”,而直接 `ConvertCents(cents)` 结尾为“壹分”。

**需要精确整数分时,请直接使用 `ConvertCents`**,不要先经过 float64 换算。它不会修复调用方在传入前已经发生的精度丢失。

## 支持范围

- 格式化支持整数部分最多 **20 位**(含四舍五入进位);不代表 float64 能逐分表示整个范围;
- 超出返回 `ErrOutOfRange`(`|amount| ≥ 10^20`);
- `ConvertCents` 支持 `int64` 全范围(约 ±9.2×10¹⁶ 元)。

## 命名说明

核心函数命名为 **`Convert`**(`Convert(amount float64) (string, error)`):

- 语义直观:把金额"转换"成大写字符串,不预设调用方领域(金额/金额/款额);
- 与 Go 标准库 `strconv` 的转换函数命名风格一致;
- 精确路径以单位后缀区分:`ConvertCents`。

若你偏好 `ToUpper` / `AmountToChinese` 等别名,欢迎提交 PR 讨论;当前公开 API 以 `Convert` 为准。

## 测试与质量

```bash
gofmt -l .       # 无输出即干净
go vet ./...     # 无告警
go test ./...    # 单元测试全过
go test -race ./...            # 竞态检测
go test -run xxx -fuzz '^FuzzConvert$' -fuzztime 10s .   # 模糊测试
```

覆盖点:

- **整数**:0、个位、十百千、万、亿,含任务基准例 `12345678.90 → 壹仟贰佰叁拾肆万伍仟陆佰柒拾捌元玖角`;
- **小数**:角、分、无小数写"整"、不足壹角(`0.05 → 伍分`)、`0 元 → 零元整`;
- **零规则**:`1001 / 105 / 100` 及跨组零(`10000001`、`100010000` 等)全表驱动;
- **负数**:整数、小数、纯分;
- **边界**:`0.00`、`-0.0`、亿级以上大数、四舍五入进位(`0.999 → 壹元整`)、`1e20` 报错、`math.MaxInt64`/`math.MinInt64` 分值;
- **等价性**:小范围 `Convert(c/100)` 与 `ConvertCents(c)` 结果一致;
- **模糊测试**:`FuzzConvert` 任意 float64 不 panic 且输出合法;`FuzzConvertCents` 额外校验符号/结尾结构不变量。
